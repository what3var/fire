# The modes of the x86 processor (`#import "x86"`)

A program in the real mode of DOS (`dos16`) switches into the **32-bit protected mode** - flat memory, all 4 GB - or into the **64-bit long mode**, runs
a routine there and comes back, or reads and writes the memory above 1 MB on the way. On every other target (and in the virtual machine) the processor is in the mode of its operating
system: every call is an `X86Exception`, `X86.Mode()` is `"none"`.

```
#import "x86"

if (X86.CanSwitch()) {
    byte code[] = new byte[3]                  // REP MOVSB, RET: the routine of X86.Move
    code[0] = 243; code[1] = 164; code[2] = 195
    var r = new X86Registers()
    r.esi = 0x100000                           // from the second megabyte
    r.edi = X86.LinearOf(buffer)               // into a buffer of the program
    r.ecx = buffer.length
    X86.RunProtected(code, r)

    var bytes = X86.ReadLinear(0xB8000, 160)   // the first line of the text screen
}
```

| Member | Meaning |
|---|---|
| `X86.Mode()` | `"real"` (the switch is possible), `"v86"` (virtual 8086 mode: EMM386, QEMM, Windows - the switch would need VCPI or DPMI), `"none"` |
| `X86.CanSwitch()` | true when `RunProtected` can switch here (a 386 or later, real mode) |
| `X86.EnableA20()` | turns the A20 line on (BIOS `int 15h`, else the system control port 92h): true when it is on - without it every second megabyte is the one below |
| `X86.RunProtected(code, r)` | runs the 32-bit machine code `code` (it ends with `RET`) in the protected mode with EAX..EDI from `r`; afterwards `r` holds what the routine left |
| `X86.CanLongMode()` | true when the processor has the long mode (CPUID 80000001h, EDX bit 29) and the program can switch |
| `X86.RunLong(code, r)` | runs 64-bit machine code (it ends with `RET`) in the long mode; RAX..RDI get the registers of `r` zero-extended, afterwards `r` has their low 32 bits |
| `X86.LinearOf(buffer, offset = 0)` | the linear address of the bytes of a byte buffer - to hand a buffer of the program to a routine (valid while the buffer lives and keeps its size) |
| `X86.ReadLinear(address, count)` / `X86.WriteLinear(address, data)` | memory at a linear address, also above 1 MB |
| `X86.Move(from, to, count)` | bytes from one linear address to another |
| `X86Registers` | `eax`, `ebx`, `ecx`, `edx`, `esi`, `edi` |

**What the routine finds:** CS = 08h (code, 32 bit, base 0, 4 GB), DS = ES = FS = GS = SS = 10h (data, the same), a stack of 4 KB, the direction flag clear,
interrupts and the NMI off with an empty IDT. A fault (a wrong address, an invalid instruction) cannot be caught there: the processor resets the machine.
While the routine runs no interrupt is served - the clock of the BIOS stands still, keys and the serial port wait; keep it short.

**In the long mode:** CS = 08h (64 bit), DS = ES = SS = 10h, the first 4 GB mapped 1:1 with pages of 2 MB (the routine and its buffers lie below 1 MB anyway),
interrupts off, a stack of 4 KB.

**How it works** (`packages/x86/native/`): a stub of 305 bytes (`tools/x86_protected.asm`, assembled with `tools/build_stubs.sh` into `fire_x86_stubs.h`) lies at
a paragraph of its own. It saves the registers, turns interrupts and the NMI off, loads a GDT (flat code and data, and 16-bit code and data at the stub for the
way back), sets PE in CR0, jumps into the 32-bit code, calls the routine, jumps to the 16-bit code, clears PE and returns to the program in real mode with the
vectors of the real mode. The long mode has a stub of its own (`tools/x86_long.asm`, 430 bytes): from the 32-bit protected mode it turns on PAE, loads
CR3 with page tables the C side builds (PML4, PDPT, four page directories: 24 KB in conventional memory), sets EFER.LME, turns paging on and jumps into
64-bit code; back it jumps to 32-bit code, turns paging off (that leaves the long mode), clears LME and PAE and goes the way of the other stub.

**Tests:** the protected mode in DOSBox-X from a fire program (registers, memory above 1 MB, a buffer of the program). DOSBox-X has no 64-bit processor:
both stubs are also booted under QEMU without DOS (`tools/test_boot.asm`: loads them, runs a 32-bit and a 64-bit routine, prints the registers to COM1).
The long mode from a fire program under DOS on a 64-bit machine is not tried yet (it needs a DOS for QEMU, e.g. FreeDOS).
