# Data models (`.fdata`)

A data model is a file of the project: `Shop.fdata`, JSON that reads well in a diff. forge turns it into fire code at build time - the classes of its
entities with the attributes of the [mapping](README.md#mapping-objects-and-tables), its enums and records, `Shop.Model` and `Shop.Context`. A project
compiles every `.fdata` in its folders (like `.fxml` and `.biscuit`); a program of single files takes it with `#include "Shop.fdata"`;
`forge fdata Shop.fdata [-o file]` writes the generated code to look at it. The generated code is not edited: a class of the program can derive from
an entity, helpers go elsewhere. The designer of spark edits the same file (the diagram is part of it).

```json

  "format": 1,
  "namespace": "Shop",
  "naming": { "tables": "snake_plural", "columns": "snake" },
  "enums": [ { "name": "Level", "values": ["Low", "Mid", "High"], "comment": "How important a customer is" } ],
  "types": [ { "name": "Address", "fields": [ { "name": "city", "type": "string" }, { "name": "zipCode", "type": "string" } ] } ],
  "entities": [
    { "name": "Customer", "comment": "Someone who buys",
      "fields": [
        { "name": "id", "type": "int", "key": true },
        { "name": "fullName", "type": "string", "length": 100, "required": true },
        { "name": "email", "type": "string", "length": 200, "unique": true },
        { "name": "level", "type": "Level" },
        { "name": "born", "type": "DateTime" },
        { "name": "address", "type": "Address", "json": true },
        { "name": "version", "type": "int", "version": true }
      ] },
    { "name": "Purchase", "fields": [ { "name": "id", "type": "int", "key": true }, { "name": "total", "type": "float", "required": true } ] },
    { "name": "Category", "table": "categories", "fields": [ { "name": "code", "type": "string", "key": true, "length": 20 }, { "name": "label", "type": "string" } ] }

  "relations": [
    { "kind": "one-to-many", "from": "Customer", "to": "Purchase", "navigation": "purchases", "inverse": "customer" },
```

## The parts

| | |
|---|---|
| `namespace` | the namespace of the generated code (default: the name of the file) |
| `naming.tables` | the table of an entity without `table`: `name` (the entity's name, the default), `plural` (`Customers`), `snake` (`order_line`), `snake_plural` (`order_lines`) |
| `naming.columns` | `field` (the field's name, the default) or `snake` (`fullName` in the column `full_name` - a `[Column]` where they differ) |
| `enums` | `name`, `values`, `comment` - an enum, stored by the name of its value |
| `types` | records stored as JSON in a column (`"json": true` on the field): `name`, `fields`; the record gets a constructor with all fields |
| `entities` | `name`, `table`, `comment`, `record` (true: a record, not a class), `set` (the name of its query in the Context; default: the plural of the name), `fields` |
| a field | `name`, `type` (`int`, `float`, `bool`, `string`, `char`, `bytes`, `DateTime`, an enum or a type of the model), `key`, `generated` (false: `[Key "manual"]` - an int key the program gives), `required`, `length`, `unique`, `index`, `version`, `json`, `column`, `comment` |
| `relations` | `one-to-many`: `from` has many `to`; the foreign key `foreignKey` (default `customerId`) is a field of `to` (added with an index when the entity has none), `navigation` the list in `from` (`[HasMany]`), `inverse` the object in `to` (`[BelongsTo]`) - one of them at least. `many-to-many`: `navigation` the list in `from`, `inverse` the list in `to` (both `[ManyToMany]`), `joinTable` (default `purchase_category`), `fromColumn`, `toColumn` (default `purchaseId`, `categoryId`) |
| `diagrams` | the boxes of the designer (spark): their places; forge does not read it |

An entity needs a key: a field with `"key": true` or a field `id`; a key is an `int` (generated by the database unless `"generated": false`) or a
`string`. forge reports every mistake of a model at once, with its line: a name fire does not allow (or a keyword), a type it does not know, a name
declared twice, two entities with the same table, an entity without a key, a relation of an entity that is not there.

## What is generated

```fire
namespace Shop {
    enum Level { Low, Mid, High }
    record Address { string city; string zipCode; construct(string city, string zipCode) { ... } }
    [Table "customers"]
    class Customer {
        [Key] int id
        [Column "full_name"] [Required] [Length 100] string fullName
        ...
        [HasMany "customerId"] List<Purchase> purchases
        construct() { }
    }
    ...
    class Model {
        static any Types()                  // ["Shop.Customer", "Shop.Purchase", "Shop.Category"]
        static any Tables()                 // ["customers", "purchases", "categories"]
    }
    class Context {
        construct(Data.Connection db)
        Data.Connection Connection
        Data.Query<Customer> Customers      // db.From<Customer>() - one per entity
        Data.Session Session()
        undefined Ensure()                  // db.Ensure of every entity
        int Migrate()                       // db.Migrate()
        string Script()                     // the DDL of the model in the dialect of the connection (db.CreateScriptOf(Model.Types()))
    }
}
```

```fire
var ctx = new Shop.Context(new Data.Connection("sqlite:shop.db"))
ctx.Ensure()
List<Shop.Customer> big = ctx.Customers.Where(c => c.level == Shop.Level.High).Include(c => c.purchases).ToList()
print(ctx.Script())
```

## The model and the database

The classes of a model have `[Table]`, so `forge data diff` sees them: after a change of the model, `forge data diff App.fireproj --url ... -o
Migrations/M3.fire` writes the migration that the database lacks into the project (it is compiled with it), `forge data migrate` runs it
([migrations](README.md#migrations)). `forge data import --url ...` gives classes for an existing database, `forge data import --url ... --format fdata -o Shop.fdata` a model
file: the tables as entities, the relations guessed from the columns (`customerId` or `customer_id` with a table `customer(s)`: one-to-many; a
table of two such columns only: many-to-many with its join table).

## The designer in spark

spark opens a `.fdata` in the designer (File > New > Data Model makes one). The file stays the text above - the designer writes it, a diff reads it.

- **The diagram** in the middle: the entities (with their fields and the navigation fields of their relations), enums and types as boxes, the
  relations as lines with `1`/`*` at their ends. Drag a box to move it (its place is saved in `diagrams`), click a box or a line to select it, Del
  deletes it (an entity with its relations).
- **The toolbox** above: `+ Entity` (with a key `id`), `+ Enum`, `+ Type`; `1 : n` and `n : m` - click the button, then the two entities (the
  first is `from`: the "one" of one-to-many). The relation gets the names the generator would choose (`purchases` and `customer`); renaming an
  entity renames them along, names of one's own stay.
- **The properties** on the right: of the model (namespace, naming), of an entity (name, table, the query of the Context, comment, record) with its
  fields as a grid (name, type - the enums and types of the model among them -, key, required, length, unique, index; up, down, delete; below the
  rest of the selected field: column, comment, generated key, version, JSON), of an enum (its values, one per line), of a type, of a relation
  (kind, the two entities, navigation, inverse, foreign key or join table and its columns).
- **Problems** below: what a build would report, with the names that are words of SQL (legal - they are quoted - but hand-written SQL must quote them).
- **Preview** below: the fire code forge makes, or the DDL for SQLite, MySQL/MariaDB, SQL Server or the in-memory database (without a connection).
- **With a database** (the URL, user and password are asked): *Import from database…* replaces the model by the tables of the database (Undo brings
  the model back); *Generate database…* makes what is missing of the model in it (`Ensure` of every entity, nothing is dropped); *Generate
  migration…* compares the project the model belongs to (the nearest `.fireproj`) with the database and writes the migration it lacks as
  `Migrations/MigrationN.fire` into the project - like `forge data diff`; the model must be saved first.
- Undo/Redo cover every change (also a moved box).
